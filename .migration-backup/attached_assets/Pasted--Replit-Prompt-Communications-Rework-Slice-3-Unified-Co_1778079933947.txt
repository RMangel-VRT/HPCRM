# Replit Prompt — Communications Rework, Slice 3 (Unified Communications Page with Secondary Nav)

## Context

Slices 1 and 2 are complete. The backend now scopes mailbox-derived data per user with role-based defaults, captures both inbound and outbound Gmail mail, and dedupes against CRM-sent communications. This is **Slice 3 of 4** and it's the visible payoff: collapse `CommunicationsCenter` and `UnsortedInboxPage` into a single page with secondary navigation.

The new page is `/dashboard/communications` and has four sub-tabs:
- **Inbox** — inbound mail in the user's scope
- **Sent** — outbound mail in the user's scope
- **Unsorted** — triage queue in the user's scope
- **All Communications** — the existing global filtered list (admin/office only)

A `viewAs` selector in the page toolbar lets admin/office users narrow to a specific user or mailbox. All four tabs share that selector and the search/date-range state, so switching tabs preserves context.

## Page structure

`client/src/pages/CommunicationsCenter.tsx` becomes a thin shell:

```tsx
<CommunicationsPageShell>
  <CommunicationsToolbar />               {/* search, date range, viewAs picker */}
  <CommunicationsSecondaryNav active={tab} />
  {tab === "inbox" && <InboxTab />}
  {tab === "sent" && <SentTab />}
  {tab === "unsorted" && <UnsortedTab />}
  {tab === "all" && <AllCommunicationsTab />}
</CommunicationsPageShell>
```

The active tab is controlled by URL: `/dashboard/communications/inbox`, `/dashboard/communications/sent`, `/dashboard/communications/unsorted`, `/dashboard/communications/all`. Default route `/dashboard/communications` redirects to the role-appropriate landing tab:
- `admin` / `office` → `inbox` (their own; `viewAs=all` accessible from the picker)
- `field` → `inbox`
- everyone else → `inbox`

If a user has no connected mailbox, `inbox` and `sent` show an empty state with a CTA: "Connect your mailbox in Settings → Mailbox Accounts".

## New components

Create under `client/src/components/customer/communications/`:

- `CommunicationsPageShell.tsx` — wraps the page, holds shared state in a context: `{ search, fromDate, toDate, viewAs, setViewAs, ... }`.
- `CommunicationsToolbar.tsx` — search input, date-range picker, `MailboxViewAsPicker` (already drafted in Slice 1; finalize here).
- `CommunicationsSecondaryNav.tsx` — pill-style tabs that match the existing CRM secondary-nav style (look at `CustomerDetail.tsx` or another page that uses secondary nav for the pattern). Each tab shows a count badge: Inbox shows unread count for inbound in scope, Unsorted shows pending count, Sent shows count for current date filter, All shows total filtered count.
- `InboxTab.tsx` — list of inbound communications in scope. Reuses the existing communications list-item component if there is one. Clicking a row opens the existing `CommunicationsQuickViewModal`. Includes filters: customer, from-address contains, has-attachments.
- `SentTab.tsx` — list of outbound communications in scope. Same item component, plus a `Status` column (sent/draft/scheduled/failed). Filter for "sent via CRM" vs "sent in Gmail" using `routingMethod` (CRM-sent rows have no router run, so they have NULL `routingMethod`; Gmail-direct sends have `routingMethod = "email_match" | "thread_match" | "content_match"`).
- `UnsortedTab.tsx` — extracted from current `UnsortedInboxPage`. Adds a direction filter (`inbound` | `outbound` | `all`) wired to the new `direction` query param from Slice 2. Triage actions (assign to customer, mark spam, archive) unchanged.
- `AllCommunicationsTab.tsx` — extracted from current `CommunicationsCenter`. Keep all existing filters (type, status, customer, direction, date, mailboxIds). Visible only to `admin` and `office`; for other roles the tab isn't rendered in the secondary nav.

All four tabs read from the existing list endpoints (with the new `viewAs` and `direction` params from Slices 1 and 2):
- Inbox: `GET /api/communications?direction=inbound&viewAs=...`
- Sent: `GET /api/communications?direction=outbound&viewAs=...`
- Unsorted: `GET /api/unsorted-emails?status=pending&viewAs=...&direction=...`
- All: `GET /api/communications?viewAs=...` (with whatever extra filters)

Use TanStack Query and key the cache by `[endpoint, viewAs, ...filters]` so switching tabs and toggling viewAs is fast.

## Routing changes

`client/src/App.tsx`:

```tsx
<ProtectedRoute path="/dashboard/communications/:tab?" component={CommunicationsCenter}
  allowedRoles={["admin", "office", "field_manager", "chemical_manager", "field",
                 "irrigation_manager", "shop_manager", "mapping", "landscape_supervisor"]} />
```

Inside `CommunicationsCenter`, read `:tab` and gate `all` to admin/office (other roles get a 404 within the page if they URL-hack to `/all`).

Keep `/dashboard/communications/unsorted` as a path that resolves to `?tab=unsorted` for back-compat in Slice 3 — Slice 4 deprecates the standalone path entirely.

## Toolbar shared state

Use a small React Context in `CommunicationsPageShell`. State persisted to URL (search, fromDate, toDate, viewAs) so a teammate can share a deep link to a specific view. Ephemeral state (selected row, scroll position) lives in component state.

## Sidebar nav

## Empty states

Each tab needs a thoughtful empty state:
- Inbox empty: "No mail in this view. Connect your mailbox in Settings or change the View As filter."
- Sent empty: "Nothing sent in this view yet."
- Unsorted empty (good!): "Inbox zero. Nothing to triage." with a checkmark.
- All empty: "No communications match these filters."

## Mobile
