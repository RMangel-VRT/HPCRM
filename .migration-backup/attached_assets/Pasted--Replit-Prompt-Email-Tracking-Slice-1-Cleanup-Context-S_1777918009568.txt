# Replit Prompt — Email Tracking Slice 1 Cleanup

## Context

Slice 1 of the Email Tracking System (PR #210, schema + UI shell) was reviewed and is substantially complete. This prompt fixes two specific issues that need to be resolved before moving to Slice 2 (Gmail OAuth). The changes are small and surgical — do not refactor or modify anything outside what's described below.

## Fix 1: Remove duplicate `inReplyTo` field on `communications` table

**Problem:** The `communications` table now has two fields that mean the same thing:

- `inReplyTo: varchar("in_reply_to")` — existing field at `shared/schema.ts` line 2519
- `inReplyToMessageId: text("in_reply_to_message_id")` — added during Slice 1 at `shared/schema.ts` line 2547

These are semantically identical (both store the RFC 822 `In-Reply-To` header for email threading). Having both will cause future bugs where code writes to one and reads from the other.

**Action:**

1. In `shared/schema.ts`, **delete** the `inReplyToMessageId` line from the `communications` table definition. Keep the existing `inReplyTo` field as-is.
2. In `shared/schema.ts`, **delete** the `inReplyToMessageId` field from the `insertCommunicationSchema` `.extend({...})` block.
3. In `server/routes.ts`, in the `migrateEmailTrackingTables()` function, **delete** the line:
   ```
   await db.execute(sql`ALTER TABLE communications ADD COLUMN IF NOT EXISTS in_reply_to_message_id TEXT`);
   ```
4. Add a new line at the end of `migrateEmailTrackingTables()` to drop the orphaned column from any database that already has it:
   ```
   await db.execute(sql`ALTER TABLE communications DROP COLUMN IF EXISTS in_reply_to_message_id`);
   ```
5. Search the entire codebase (both `client/` and `server/`) for any references to `inReplyToMessageId` or `in_reply_to_message_id`. If found, replace with `inReplyTo` / `in_reply_to`. Likely zero hits since the field hasn't been written to yet, but verify.

## Fix 2: Add missing OAuth placeholder fields to `mailbox_accounts` table

**Problem:** The Slice 1 spec called for four OAuth-related placeholder fields on the `mailbox_accounts` table that didn't get added. Slice 2 (Gmail OAuth) requires these fields to function — specifically `oauthTokenJson` is where Gmail refresh tokens will be stored. Adding them now keeps the schema clean rather than backfilling them mid-Slice-2.

**Action:**

1. In `shared/schema.ts`, in the `mailboxAccounts` table definition (around line 2411), add these four fields. Place them between `syncStatus` and `createdAt`:

   ```
   syncEnabled: boolean("sync_enabled").notNull().default(false),
   lastSyncedAt: timestamp("last_synced_at"),
   oauthProvider: text("oauth_provider"),
   oauthTokenJson: jsonb("oauth_token_json"),
   ```

2. In `shared/schema.ts`, update `insertMailboxAccountSchema`'s `.extend({...})` block to include the new optional fields:

   ```
   syncEnabled: z.boolean().default(false),
   lastSyncedAt: z.coerce.date().nullable().optional(),
   oauthProvider: z.string().nullable().optional(),
   oauthTokenJson: z.any().nullable().optional(),
   ```

3. In `server/routes.ts`, in the `migrateEmailTrackingTables()` function, add four `ALTER TABLE` statements after the existing `mailbox_accounts` `CREATE TABLE` block (and before the `unsorted_emails` `CREATE TABLE` block):

   ```
   await db.execute(sql`ALTER TABLE mailbox_accounts ADD COLUMN IF NOT EXISTS sync_enabled BOOLEAN NOT NULL DEFAULT false`);
   await db.execute(sql`ALTER TABLE mailbox_accounts ADD COLUMN IF NOT EXISTS last_synced_at TIMESTAMP`);
   await db.execute(sql`ALTER TABLE mailbox_accounts ADD COLUMN IF NOT EXISTS oauth_provider TEXT`);
   await db.execute(sql`ALTER TABLE mailbox_accounts ADD COLUMN IF NOT EXISTS oauth_token_json JSONB`);
   ```

4. The existing `syncStatus` field stays — it represents UI-facing status (`not_connected` | `connected` | `error`). The new `syncEnabled` is a separate boolean for "should the background sync worker actually pull from this mailbox." They serve different purposes and should both exist.

5. No UI changes required for these fields. The Mailbox Accounts settings page can continue to show only what it currently shows. The new fields are placeholders that Slice 2 will populate.
