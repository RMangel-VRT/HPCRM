## 2. Service programs (new owned fact)

"When do the rounds fall, for a service and count, when the contract doesn't say." Owned here and nowhere else.

```sql
CREATE TABLE IF NOT EXISTS service_programs (
  id varchar PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id varchar NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  service_key text NOT NULL,                 -- a catalog key with scheduling = 'campaign'
  rounds smallint NOT NULL CHECK (rounds BETWEEN 1 AND 24),   -- the contract count this row answers
  month_spread smallint[] NOT NULL CHECK (array_length(month_spread, 1) = 12),
  is_standard boolean NOT NULL DEFAULT false,  -- the count used when a contract includes the service but states no count
  updated_by_id varchar REFERENCES users(id) ON DELETE SET NULL,
  created_at timestamp NOT NULL DEFAULT now(),
  updated_at timestamp NOT NULL DEFAULT now(),
  CONSTRAINT service_programs_unique UNIQUE (company_id, service_key, rounds)
);
CREATE UNIQUE INDEX IF NOT EXISTS service_programs_one_standard
  ON service_programs (company_id, service_key) WHERE is_standard;
```

**Precedence (Randy, Nov 10), used by CG2:**
1. **Count:** the season's stated `quantity` always wins. If it's blank, use the service's **standard** row (`is_standard`), if one is set. If neither, it's a `no_count` gap. **Never fall back to the catalog's `defaultQuantity`** (chemical's is 12, which matches no contract).
2. **Months:** the season's stated `month_spread` always wins. Otherwise, the program row for `(service, count)`; the standard row is also the program row for its own count.
3. Counts are never edited per customer outside the Contract Center; changing a season's count moves its rounds on the next reconcile (CG3).

- **Validation (shared zod, used by API and client):** `service_key` is a campaign service; 12 non-negative integers; **the sum equals `rounds`**; at most 4 in any one month. Setting `is_standard` on a row clears it from the service's other rows in the same transaction.
- **No seed rows.** Randy enters them. Until a row exists, CG2 reports the gap instead of guessing. (The catalog's `defaultMonthSpread` is a contract-editor prefill and is **not** a program; e.g. chemical's default is 12 applications, which matches no current contract.)
- **API** (allow-list roles: GET admin + office; PUT/DELETE admin):
  - `GET /api/service-programs` → rows, plus `countsInUse`: for each campaign service, the distinct counts found on included scope lines of seasons that are signed/active/renewed/sent and haven't ended, **with how many seasons have no month spread** for that count, and **`noCount`: how many seasons include the service with a blank quantity** (those use the standard). This is what tells Randy which rows he needs.
  - `PUT` accepts `{ monthSpread, isStandard }`.
  - `PUT /api/service-programs/:serviceKey/:rounds` (upsert) and `DELETE` the same path.
- Mirror in `schema.ts` and the client schema copy.

## 3. Settings → Scheduling → Service timing

One small page under the existing Settings hub (find where the Crews and Routes settings sit; follow that section's layout).

- One card per campaign service. In each card, one row per count in `countsInUse` plus any saved row: "**3 rounds** · used by 29 seasons without stated months" and twelve month cells (Jan…Dec) holding a number (blank = 0). A running "3 of 3 placed" check; Save is enabled only when it adds up.
- A row with seasons needing it and no program shows a warning chip: "No timing set: 29 seasons can't be scheduled".
- **Standard** at the top of each card: "When a contract includes tree pruning but gives no count: **[count] rounds**" plus its twelve month cells, and "used by 33 seasons". Choosing a count picks or creates that count's row and marks it standard. Leaving it empty shows "No standard: 33 seasons need a count on their contract". A standard is optional for every service, including fert/chem.
- Saved rows not used by any season show muted, with Delete.
- Explanatory line at the top: "Used only where a contract is silent. A contract's own count and months always win. Changing timing here never changes a contract."
- Office sees the page read-only.

## 4. Campaign columns

```sql
ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS source text NOT NULL DEFAULT 'manual';
ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS service_key text;
ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS round_month date;      -- first day of the round's month
ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS round_seq smallint;    -- 1 unless a program/contract puts 2+ rounds in one month
-- CHECK source IN ('manual','contract') (guarded DO block, as in 0072)
-- CHECK source = 'manual' OR (service_key IS NOT NULL AND round_month IS NOT NULL AND round_seq IS NOT NULL)
CREATE UNIQUE INDEX IF NOT EXISTS campaigns_contract_round_unique
  ON campaigns (company_id, service_key, round_month, round_seq) WHERE source = 'contract';
```

- Existing rows become `manual` by the default. **No backfill** of service keys onto old campaigns.
- Expose `source`, `serviceKey`, `roundMonth`, `roundSeq` on the campaign read endpoints, and include `campaign.serviceKey` wherever campaign items are returned with their campaign (the customer Services hook already reads `i.campaign?.serviceKey`).
- **Generated campaigns are read-only in shape:** the existing campaign edit endpoint rejects changes to `title`, `window_start`, `window_end`, `category`, `subtype`, `service_key`, `round_month`, `round_seq` and `source` when `source = 'contract'` (409 with a message). Status (archive/complete), assignees, description and notification template stay editable.
- **Manual add/remove of items is blocked on generated campaigns** (409: "Membership follows contracts. Change the property's contract scope."). Manual campaigns keep today's behavior.

## 5. Visit ↔ campaign item link

```sql
ALTER TABLE visits ADD COLUMN IF NOT EXISTS campaign_item_id varchar REFERENCES campaign_items(id) ON DELETE NO ACTION;
CREATE UNIQUE INDEX IF NOT EXISTS visits_campaign_item_done_unique
  ON visits (campaign_item_id) WHERE campaign_item_id IS NOT NULL AND status = 'done';
-- CHECK source_type <> 'campaign_item' OR campaign_item_id IS NOT NULL (guarded)
CREATE INDEX IF NOT EXISTS visits_campaign_item_idx ON visits (campaign_item_id);
```

- zod: `campaignItemId` in `visitFields`; `superRefine` requires it when `sourceType === "campaign_item"`.
- Round work isn't pre-dated: CG4 records one **done** visit when an item is completed. At most one done visit per item.
- Nothing creates these visits yet (CG4).
