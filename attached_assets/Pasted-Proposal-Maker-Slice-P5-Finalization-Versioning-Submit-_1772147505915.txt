Proposal Maker — Slice P5 (Finalization + Versioning) — Submit This Whole Block
Goal

Add finalization and versioning so proposal outputs become permanent, auditable records. Users must be able to finalize a proposal, preserve that version forever (unchanged), and create new versions without overwriting prior versions.

Guardrails (What NOT to build yet)

Do not add email sending, automation, approvals, or e-signature

Do not add templates or proposal-type libraries

Do not parse QuickBooks estimate data

Do not introduce complex role sharing (client portals, etc.)

Keep the workflow simple, reliable, and audit-friendly

Core Definitions (Must-Haves)
Draft

Editable proposal record tied to a customer

Can regenerate PDF anytime

Can replace estimate PDF and modify scope/images

Finalized Version

Immutable snapshot of a proposal at a point in time

Must remain downloadable and readable forever

Must not change even if the draft later changes

Version Labeling

Finalized proposals are labeled sequentially:

v1, v2, v3…

Version numbers are per customer proposal stream (per proposal “family”), not global

Requirements
1) Proposal “Family” Concept (Minimal)

Each customer can have multiple proposals. Each proposal can have multiple versions. P5 introduces a minimal “proposal family” grouping so versions stay together.

Behavior

The first time a draft is finalized, it becomes v1 in its family

Any new version created from that proposal becomes v2, v3, etc.

(No need for complicated naming—just ensure versions group together logically.)

2) Finalize Action (Draft → Finalized Version)

Add a “Finalize Proposal” action on the Draft page (Admin + Office only).

When clicked:

System generates the full combined PDF using current Slice P4 behavior:
branded + estimate + appendix (if images exist)

System creates a Finalized Version record with:

Customer reference

Proposal family reference

Version label (v#)

Finalized by / finalized date-time

Title + proposal date (captured as-of finalization)

Optional estimate number (captured as-of finalization)

System stores a frozen PDF artifact for that version (immutable)

System locks that finalized version so it cannot be edited

Important

If PDF generation fails for any reason, finalization fails and no finalized version is created

3) Immutable Storage Rules (Critical)

Finalized versions must be immutable by design:

The finalized version’s PDF must never change

The finalized version must remain downloadable even if:

the draft changes later

files are replaced in the draft

images are removed from the draft

estimate is replaced in the draft

This means the finalized version must be backed by a stored PDF artifact (not regenerated later from the draft).

4) New Version Workflow (Create v2+)

Add “Create New Version” action visible when viewing a finalized version.

Behavior:

Creates a new Draft pre-populated with:

Title, proposal date, estimate number

Scope text

References to the current estimate PDF and images (or copies—implementation choice)

The new draft is editable and can later be finalized as the next version (v2, v3…)

Rule

Creating a new version must not modify the prior finalized version.

5) Status + UI Display
On Customer → Proposals List

Show proposals grouped by family with version visibility:

Proposal family title

Latest version label (e.g., v3)

Latest status (Draft or Finalized)

Proposal date

Last updated / finalized date

When opened, user can see:

Draft (if one exists)

Version list: v1, v2, v3… each downloadable

On Draft Page

Status badge: Draft

Button: Finalize Proposal

On Finalized Version Page

Status badge: Finalized (v#)

Download PDF button

Button: Create New Version

6) Permissions

Same as earlier slices unless changed later:

Admin + Office: can create/edit drafts, finalize, create new versions, download any version

Other roles: no access

Acceptance Tests

Finalize creates v1 and stores an immutable PDF artifact

Finalized PDF remains downloadable after draft edits/replacements

Finalized version cannot be edited

Create New Version from v1 creates a new editable draft

Finalizing that new draft creates v2 (increments correctly)

Versions list shows v1 and v2, both downloadable, unchanged

Finalization fails cleanly if PDF generation fails (no partial version created)

Customer proposals list shows correct grouping and latest version status

Done Definition

Users can finalize a proposal into an immutable version (v1, v2, …), preserve historical versions permanently, and create new editable versions without overwriting or altering any previous finalized proposal output.
