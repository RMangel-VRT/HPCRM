# Replit Prompt — Mailbox Backfill: Stuck-Run Recovery + Force-Cancel

## Context

A backfill run finished its work but the My Mailbox UI keeps showing it as "running". Symptom: a row in `mailbox_backfill_runs` has `status = 'running'` (or `'queued'`) but no worker is actually processing it — the Node process was killed mid-run (Replit restart, deploy, OOM, crash). When the server came back up, `requeueInterruptedBackfills()` was supposed to recover it, but for some runs it doesn't, and there is no user-visible way to clear the stuck row. Worse, the existing Cancel button is a no-op in this state: `POST /:id/backfill/:runId/cancel` only sets `cancel_requested = true`, and that flag is only read inside the worker's main loop — if no worker is alive, the row never transitions.

This slice fixes the underlying durability gap (no way to tell a stuck run from an active run), unblocks the existing stuck row, and makes the Cancel button actually work in the dead-worker case.

This must land in a deployable, production-quality state. No stubs, no `// TODO` comments hiding incomplete code paths.

## Step 3 — Stale-run reaper on startup

In `artifacts/api-server/src/services/mailboxBackfillService.ts`, rewrite `requeueInterruptedBackfills` (currently line 445) so it splits dead runs from genuinely-interrupted ones:

```ts
const STALE_THRESHOLD_MS = 10 * 60 * 1000; // 10 minutes

export async function requeueInterruptedBackfills(): Promise<void> {
  try {
    type RunRow = typeof mailboxBackfillRuns.$inferSelect;
    const result = await db.execute<RunRow>(
      sql`SELECT * FROM mailbox_backfill_runs WHERE status IN ('queued', 'running') ORDER BY started_at ASC`
    );
    const rows: RunRow[] = (result as unknown as { rows: RunRow[] }).rows ?? [];
    if (rows.length === 0) return;

    const now = Date.now();
    const stale: RunRow[] = [];
    const healthy: RunRow[] = [];
    for (const run of rows) {
      const lastBeat = (run.updatedAt ?? run.startedAt ?? run.createdAt)?.getTime?.() ?? 0;
      if (now - lastBeat > STALE_THRESHOLD_MS) stale.push(run);
      else healthy.push(run);
    }

    if (stale.length > 0) {
      console.warn(`[backfill] Marking ${stale.length} stale run(s) as error (no heartbeat in >${STALE_THRESHOLD_MS / 60000}m)`);
      for (const run of stale) {
        await storage.updateMailboxBackfillRun(run.id, {
          status: "error",
          finishedAt: new Date(),
          errorMessage: "Backfill worker terminated unexpectedly. Please retry.",
        });
      }
    }

    if (healthy.length > 0) {
      console.log(`[backfill] Re-queuing ${healthy.length} interrupted backfill run(s)`);
      for (const run of healthy) {
        await storage.updateMailboxBackfillRun(run.id, { status: "queued", cancelRequested: false });
        setImmediate(() => {
          runBackfill(run.id).catch(err => {
            console.error(`[backfill] Requeue error for run ${run.id}:`, err);
          });
        });
      }
    }
  } catch (err) {
    console.error("[backfill] Error in requeueInterruptedBackfills:", err);
  }
}
```

Confirm `requeueInterruptedBackfills` is called from `artifacts/api-server/src/index.ts` after the DB is ready (it already is — do not move it, just verify).

## Step 4 — Make cancel work when the worker is dead

In `artifacts/api-server/src/services/mailboxBackfillService.ts`, replace `requestCancel` (currently line 431) with a version that force-cancels stale rows instead of leaving them in limbo:

```ts
const CANCEL_STALE_THRESHOLD_MS = 60 * 1000; // 1 minute

export async function requestCancel(runId: string): Promise<void> {
  const [run] = await db
    .select()
    .from(mailboxBackfillRuns)
    .where(eq(mailboxBackfillRuns.id, runId));
  if (!run) return;

  const lastBeat = (run.updatedAt ?? run.startedAt ?? run.createdAt)?.getTime?.() ?? 0;
  const isStale = Date.now() - lastBeat > CANCEL_STALE_THRESHOLD_MS;

  if (isStale && (run.status === "running" || run.status === "queued")) {
    // No worker is processing this — flip status directly so the UI clears.
    await storage.updateMailboxBackfillRun(runId, {
      status: "cancelled",
      finishedAt: new Date(),
      cancelRequested: true,
    });
    return;
  }

  await storage.updateMailboxBackfillRun(runId, { cancelRequested: true });
}
```

Threshold rationale: the worker writes a heartbeat every 25 messages (typically << 60s of wall-clock time). A live worker will see `cancel_requested = true` on its next loop iteration and transition to `cancelled` itself. A dead worker has no chance, so we transition directly.
