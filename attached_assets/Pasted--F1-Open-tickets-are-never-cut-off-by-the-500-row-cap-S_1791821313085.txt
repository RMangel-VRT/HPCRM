# F1: Open tickets are never cut off by the 500-row cap

> Standalone slice. Read `.agents/memory/` first. Line numbers are from GitHub `b2dd122`; find code by its content. **No schema change, no migration, no data writes.** Tests use vitest. Report changed files, call sites, test results and baseline failures separately.

## Why

C1's audit found production has **545 tickets, 155 open, and 8 open tickets beyond the cap**. `storage.getTickets()` (storage.ts ~L1928) returns the newest 500 tickets, open **and** closed together. So once a company passes 500 tickets, its oldest open jobs drop off the Tickets board, My Tickets and the customer list, and nobody is told. Those are exactly the jobs most likely to be overdue. The Phase 3 Scheduling board reads the same list, so this has to be fixed first.

## Change: `storage.getTickets()`

Keep the signature and every existing filter (`customerId`, `contractId`, `assignedToId`). The result changes to:

- **every open ticket** (current status `is_final = 'false'`) matching the filters, **with no cap**, plus
- **the newest 500 closed tickets** matching the filters (`is_final = 'true'`), so closed-ticket history stays bounded.

Order the result by `created_at DESC`, as today. Use two queries, or one `UNION ALL`, joined to `ticket_type_statuses` for `is_final`. Don't call it once per ticket. A ticket whose status row is missing counts as open; check whether any exist and report the count.

Update the `// PERF` comment to describe the new contract.
