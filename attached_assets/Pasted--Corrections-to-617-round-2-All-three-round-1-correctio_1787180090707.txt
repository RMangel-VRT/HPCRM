## 2. Drop `--tc` from the header container — it is unused and only creates risk

Step 5 says the header wrapper should set `--tc`. That came from my spec, where I described it as "so descendants can use it" — but **nothing in the slice reads it.** Every colour in the header, the work-thread bar and the stepper interpolates `${hue}` directly into `color-mix(...)`.

Setting it costs something, though: React's `CSSProperties` does not accept arbitrary custom properties, so it needs a cast (`style={{ "--tc": hue } as React.CSSProperties}`) that can fail typecheck under this repo's settings — and Step 1's baseline comparison would then flag an error caused entirely by a dead variable.

**Remove `--tc` from Step 5.** The wrapper keeps only its two real styles:

```tsx
<div
  className="rounded-xl border px-3 py-3 -mx-1"
  style={{
    background: `linear-gradient(180deg, color-mix(in srgb, ${hue} var(--tt-tint2), transparent) 0%, transparent 100%)`,
    borderColor: `color-mix(in srgb, ${hue} 22%, var(--border))`,
  }}
>
```

If a later slice genuinely needs a cascading custom property, it can add one then, with a reader to justify it.
