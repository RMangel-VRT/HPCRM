Customer detail redesign — Replit implementation slices
Context for the agent
The customer detail page currently uses a horizontal tab strip with 9 top-level tabs (Overview, Contacts, Notes, Operations, Maps, Service Checklist, Communications, Billing, Settings, Service Plan), with two of those (Operations, Billing) having their own inner sub-tab strips. We're moving that navigation to a vertical sub-rail that sits between the global left nav and the main content area, promoting Overview to a real Dashboard, and flattening every sub-tab into the rail.
Stack: React 18 + TypeScript + Vite + Tailwind + shadcn/ui (Radix) + Wouter + TanStack Query. Don't add new dependencies.
Goal
Make every customer feel like its own dashboard for an account manager. The rail is the workspace navigation; the main area is fully focused on the active section.
Non-goals

No backend or schema changes. All data already exists.
No new features. Every tab and sub-tab keeps its existing content.
No mobile-specific redesign yet. Assume desktop; we'll add a collapsing rail for narrow screens later.
No drag-to-reorder dashboard cards.
No permissions/role logic changes. Wherever a tab is currently admin/office-only, the corresponding rail item is admin/office-only.

Target information architecture
The rail has a pinned customer block at the top, then five labelled sections. Customer name dropdown stays as the switcher.

Slicing approach
Each slice is meant to be one Replit Agent run that lands in a deployable state. Slices 1–3 do the structural move. 4–7 are the quality-of-life follow-ups. 8 is optional polish. Don't ship slice N+1 until slice N is reviewed.
