--- REVISE #626 (Dashboard action queue API) ---

Add a de-duplication step. Invoices already auto-create: maybeAutoCreateInvoiceOnRfb
(lib/rfbInvoiceAutoCreate.ts, called from the ticket PATCH handler in routes.ts ~L7073)
fires on any landing at ready_for_billing for Project / Estimate Request / Extra Billable,
and is idempotent. So a ticket sitting at Ready for Billing normally already has an Invoice
child at pending_invoice, and the queue as specced would show the same job twice — once as
the parent, once as the child.

Required change:
- Widen the ticketLinks bulk fetch to cover both directions in the same query.
- For each ready_for_billing row, if an invoice_for link exists with that ticket as
  sourceTicketId, DROP the row. The invoice child represents the work.
- Keep it only when no link exists — that means auto-create was skipped (ineligible type,
  or billingBehavior never became invoice_required) and the work is genuinely stranded.
- Set that surviving row's verb to "Open" and leave it as plain navigation. Do NOT wire
  POST /api/tickets/:id/create-invoice to it — that endpoint rejects Extra Billable tickets
  (routes.ts ~L7266, accepts only estimate_request and project) and returns 409 INVOICE_EXISTS
  when a link already exists.
- Recompute total and byFilter.billing AFTER the drop, not before.
- Acceptance: the queue never shows a ready_for_billing parent alongside its own
  pending_invoice child.
