Must-fix / Must-confirm (highest risk)
1) Map capture can produce a blank image unless the map is initialized for export

With Mapbox GL, map.getCanvas().toDataURL() often returns blank/black unless the map was created with a setting that preserves the drawing buffer (WebGL optimization). This is the #1 “why is my screenshot empty?” issue.

Requirement to add:

Map must be initialized in “export-safe” mode so canvas capture works reliably.

(You don’t have to name the setting in the spec, just make this a requirement.)

2) Replace workflow will leave orphan files unless you delete the old GCS object

Your flow says: upload new → PATCH overwrites old path. That will work, but the old object will remain in GCS unless explicitly deleted, which becomes real cost + clutter.

Two clean options (pick one):

Option A (recommended): When baseImagePath is replaced, server deletes the previous base image object automatically.

Option B: Keep old object for now, but add a background cleanup job later. (Not as good.)

Add requirement: “Replacing base image must delete the prior base image object to avoid orphaned storage.”

3) Don’t clear baseImagePath only in local state

Your plan says “Replace base image button clears baseImagePath in local state (not in DB) and shows capture UI.”

That’s okay during the session, but it creates a confusing edge case:

user clicks Replace → gets distracted → refreshes → old base image is still there (because DB never changed)

Better UX requirement (still simple):

Replace is a modal/overlay workflow: “Upload new base image”

Old base remains visible until new one is successfully saved

After success: patch DB + delete old object

This prevents “I thought I replaced it” confusion.

4) Object download access and permissions

You mention previewing images from a /objects/... path. Confirm that:

Admin/Office can load it

It doesn’t require public access

It doesn’t leak cross-company files

Requirement to add:

Base images must be served securely (company-scoped), not as public URLs.

Important “Professionalism” improvements (still VS1-safe)
5) Capture should be high-resolution enough for proposals

Canvas capture resolution is limited by the on-screen map size. If you capture at ~55vh, the exported PNG may look soft when inserted into a PDF.

Simple requirement:

Captured base image must be print-acceptable (target at least ~1600px wide, ideally 2000px+).

If you can’t guarantee that via canvas capture, VS2 can add a “High-res capture” method (static image request). But at least set the expectation now.

6) Attribution / copyright text must remain visible on captured imagery

Map providers often require attribution to be displayed. If the capture doesn’t include the attribution control, you can create compliance risk later.

Requirement:

Captured base image must include attribution text (either captured from the map UI or added as a small footer line on the exported image).

Even if you “don’t worry about licensing,” this is an easy safeguard.

Scope tightening (to keep VS1 from ballooning)

Your tasks are already good here. Don’t add:

overlay

combined exports

proposal integration

Those are cleanly VS2/VS3+.
