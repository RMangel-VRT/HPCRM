1. High-Level Goals

Make every ticket:

Visually grounded (photos)

Location-aware (pin on a map / GPS)

Billing-aware (contract vs extra vs project vs admin)

Simplify field crew decisions:

“Is this included, billable extra, project, or admin/estimate?”

Stop forcing crews to pick a specific contract; instead:

Use a clear classification that drives invoicing rules and reporting.

2. Ticket Types / Work Classifications

Replace the old contract-link step with a Ticket Work Type selector in the wizard:

New Work Types (single-choice, required)

Contract

Meaning: Work is included in an existing customer contract.

Billing: No separate invoice required (covered by contract).

Usage: Regular onsite maintenance tasks, contractually included cleanup, etc.

Extra Work (better label options than “Non-contract”)

Suggested label: “Extra Billable” or “Out-of-Scope”

Meaning: Work is outside the contract and must be invoiced.

Examples: Extra leaf cleanup, branch removal, extra visits at board request.

Billing: Requires invoice later.

Project

Meaning: Larger scoped work that goes through estimate → approval → execution → invoicing.

Uses the existing multi-step project workflow (8 steps).

Tied conceptually to your Estimate Builder and future project tracking.

Admin

Meaning: Internal or office work.

Examples: Email replies, board meeting prep, documentation, special requests, follow-up calls.

Billing: Generally not invoiced directly; used for time tracking / workload.

Estimate Request

Meaning: A request to price something that may become a Project or Extra Billable job.

Typically created by office/admin from calls/emails or by ops in the field.

Should be easy to convert to a Project or launch Estimate Builder.

Design choice: Estimate Request can either be its own top-level type (recommended) or live under Admin with a specific flag. I’d treat it as its own type but show it under “Admin work” in reports.

3. Data Model Adjustments (Conceptual, no code names)

Ticket fields to add / adjust:

Work Type (one of: Contract / Extra Work / Project / Admin / Estimate Request)

Billing Behavior Flag:

For internal logic:

Contract → no_invoice_required

Extra Work / Project → invoice_required

Admin / Estimate Request → no_invoice (or “internal”)

Keep the existing category/workflow concepts under the hood:

Onsite Maintenance Task (was Quick Task)

Project (8-step)

Admin/Estimate (simpler flows)

Contract ID:

Stop asking the user to pick a specific contract in the wizard.

For now, either:

Leave contractId unused, or

(Optional) Auto-link if the customer has only one active contract (no UI step).

Ticket sources table:

Keep as-is: still useful for “manual vs auto-generated later”.

4. Wizard Changes (Creation Flow)

Current: Type → Customer → Contract → Details
New:

Step 1 – Work Type

Options: Contract / Extra Work / Project / Admin / Estimate Request.

If Project selected → automatically uses the multi-step project workflow.

Step 2 – Customer

Select customer from CRM or create new.

Once selected, show basic info and current status (Active/Prospect/etc.).

Step 3 – Location (new)

Location picker:

Map-based pin drop or

Address + optional GPS field

Allow:

“Use property address” quick button.

Optional custom label: “Building C stairs”, “Back parking lot”, etc.

Step 4 – Details & Attachments

Title & description (required).

Type-specific fields:

Contract: service category (mowing, cleanup, irrigation, snow, etc.).

Extra Work: service category + internal note like “billable extra”.

Project: tie into existing steps (estimate, approvals, etc.).

Admin: category (email, meeting, paperwork, etc.).

Estimate Request: requested scope, urgency, who requested.

Photo attachments:

Multi-photo upload.

Per-photo caption/notes (e.g., “cracked curb by Unit 12”).

Assignment & due date (if part of your existing system).

Save as Draft or Create/Start.

5. Photo Attachments (Tickets)

Behavior:

Every ticket supports multiple photo attachments.

Each photo stores:

File, uploaded by, timestamp.

Optional caption.

In the ticket detail:

Show a photo gallery (thumbnails → enlarge on click).

Mobile-friendly, swipeable.

Rules:

For certain work types (e.g., Extra Work, Estimate Request, Snow-related Contract work), photos should be strongly encouraged or required:

e.g., Estimate Request must have at least one photo if location is “specific defect”.

All photos are stored with the ticket and visible on the customer → tickets view.

6. Location Pin / Map Integration

Behavior:

Each ticket can store one primary location:

Base: property address (from customer).

Optional: more specific pin and label.

In the ticket detail:

Show a small map / visual indicator with pin (or at least lat/long and text location).

On mobile: big tap target for “Open in maps”.

Workflow details:

Step 3 (Location) lets user:

Option 1: “Use main property address”

Option 2: “Drop pin on map”

Option 3: Enter a textual description (“Southwest corner parking lot”, “Unit 5 patio”).

Location becomes important for:

Onsite Maintenance and Extra Work (field crews know exactly where).

Snow Damage / Estimate Requests (calculated risk and documentation).

7. Rename “Quick Task” → “Onsite Maintenance Task”

UX changes:

In all UI where “Quick Task” appears:

Change the label to “Onsite Maintenance Task”.

Conceptually:

Onsite Maintenance Task = short, focused job in the field, often Contract or Extra Work.

Existing tickets of type “quick task”:

Just show as “Onsite Maintenance Task” in all user-facing areas.

8. Behavior by Work Type (How the system treats them)

Contract

Default assumption: No separate invoice.

Show a small “Included in contract” badge on the ticket.

In reporting, these can be aggregated against contract revenue later.

Extra Work (Out-of-Scope / Extra Billable)

Mark with “Extra Billable” badge.

Flag for follow-up in invoicing workflow (later: link to Estimate/Invoice).

Optional: allow tagging which contract it’s “related to” in read-only fashion (for your brain, not billing logic).

Project

Uses your existing multi-step project workflow (estimates, approval, execution, invoicing, completion).

Tied closely to Estimate Builder and future project dashboards.

Admin

No invoice, no contract link.

Useful for time tracking, load, and internal ops.

Estimate Request

Slim workflow: capture request details, photos, and location.

Provide a clear button: “Create Estimate from this Request” (which opens Estimate Builder pre-filled).

Once an estimate is created, show a link from the ticket to the estimate (later, to the resulting Project).
