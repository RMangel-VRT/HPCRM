# Navigation rework: rules (paste once at session start)

**Goal (Randy):**
- Every role uses the same desktop web app: the dark-green sidebar, grouped by the job being done.
- Pages that have sub-sections use one light-green side menu (the "section rail"), the way Settings will.
- Phones get the native app later. That is a separate project, so these slices don't touch it.

**Approved design:** "High Plains Navigation Model" (Claude artifact) and `claude/navigation-design.md` in the Claude project.

## Order

| Slice | What | Schema? |
|---|---|---|
| N1 | **Shell and sidebar.** Every role goes through `AppSidebar` (retire `FieldAppLayout`). New groups, top-bar Tools and New menus, profile menu. Operations is broken up into its standalone pages. | No |
| N2 | **Section rail + Settings.** A reusable rail component and tokens. Settings moves from 15 tabs to a sectioned rail, and the Seasons page merges in. | No |
| N3 | **The rail on other pages.** Tickets, Maps, Campaigns, Plant Library, Inbox, Flags, and a restyle of the customer page. The N1 stop-gap sidebar items fold in. | No |
| N4 | **Renames.** Billing → Invoicing. "Ready for Billing" → "Ready to invoice" (label only; the key stays). | DML only |
| N5 | **Estimates board.** A new page: open Estimate Request + RFP tickets by stage. | No |

Merge each slice before starting the next.

## Rules

1. **Line numbers are from GitHub `a77f060`** (P3-3 merged). Find code by its content.
2. **No DDL in any slice.** N4 has one data update. It is DML only, idempotent, guarded by an `information_schema` check, and called from `registerRoutes()` after `migrateTicketTypeRename()`, never from `runStartupMigrations()`, which is not wired up (`.agents/memory/startup-migrations-not-wired.md`).
3. **Every route keeps the `/dashboard/` prefix.** Every path that moves gets a `<Redirect>` that preserves the query string.
   - The server builds links into the app that must keep working:
     - `flags.ts` ~L299 (`/dashboard/flags/:id`, in emails)
     - `emailSyncService.ts` ~L324 (`/dashboard/settings/mailbox-accounts`, in emails)
     - `mailboxAccounts.ts` ~L277
     - `dashboardQueue.ts` (`/dashboard/tickets/:id`, `/dashboard/communications/:id`, `/dashboard/contracts/:id`)
     - `crewsAndMobile.ts` ~L1670 (visual scope editor)
   - So do old bookmarks: `/dashboard/operations`, `/dashboard/seasons`, `/dashboard/billing`.
4. **Billing visibility has two different rules, and both must stay.** `showBillingSidebar` (lib/billing.ts) decides the sidebar entry and badge: admins always see it, and office users see it only when they are *not* billing-tagged. `canViewBilling` decides access. Never use access as the sidebar rule (`.agents/memory/ticket-consolidation-scope.md`). `BILLING_LANDING` and `lib/landing.tsx` keep working.
5. **Every new or changed label goes in both `i18n/locales/en.ts` and `es.ts`.** Field staff use Spanish. Each slice lists its keys with the Spanish text to use.
6. **Stable test IDs.** Sidebar items get `data-testid="nav-<key>"`, and the key is stable even when a label changes. Today's IDs are derived from the title (`link-${title}`), so renames break them. Update every test that used the old IDs. At least `BillingAccess.regression.test.tsx`, `ContractCenter.board.test.tsx`, `CustomerContracts.rendered.test.tsx`, `TicketDetail.visits.rendered.test.tsx` and `SettingsPage.qbo.test.ts`; grep for the rest.
7. **No dead links or placeholder UI.** Calendar, Estimates (until N5) and ⌘K search don't appear until their pages exist. The two "coming soon" Tools cards go away.
8. **Stable identities:** use `typeKey` / `statusKey` and the `isSeeded*` / `findSeeded*` helpers. Never compare display names (N4 removes the last two client-side name checks).
9. **Don't touch the native app** (`artifacts/highplains-mobile`), `mobileAuth.ts` or `MOBILE_ALLOWED_ROLES`.
10. **Role permissions don't change.** Every `ProtectedRoute` `allowedRoles` stays as it is unless a slice says otherwise. The sidebar must never show a link that the route would deny.
11. **Dark mode:** every new color is a CSS token with a light and a dark value in `index.css`. No hex values in components.
12. **Tests use vitest.** Report changed files, test results, and typecheck diagnostics against the pre-edit baseline. Record the baseline before you edit, and refresh workspace declarations first (`.agents/memory/workspace-declaration-baselines.md`). Report known baseline failures separately.
