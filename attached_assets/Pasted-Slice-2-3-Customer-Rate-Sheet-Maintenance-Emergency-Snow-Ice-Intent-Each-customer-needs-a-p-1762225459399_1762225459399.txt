Slice 2.3 — Customer Rate Sheet (Maintenance, Emergency, Snow & Ice)

Intent
Each customer needs a place to store all labor and equipment rates that define how work is billed — both for regular maintenance and for snow removal.

⸻

Scope — what the user should be able to do

On each Customer profile, create a Rate Sheet section with clear groupings:

A) Maintenance & Emergency Labor (per hour)
	•	General labor
	•	Operator labor
	•	Irrigation labor
	•	Emergency general labor
	•	Emergency irrigation labor

B) Snow & Ice Services
	•	Hand shovel labor (per hour)
	•	Plow truck (per hour)
	•	ATV (per hour)
	•	Skid steer (per hour)
	•	Snow blower (per hour)
	•	Ice melt material (per pound)
	•	Ice melt application labor (per hour)

Each rate field:
	•	Shows a label and a currency input.
	•	Uses a consistent unit (per hour or per pound).
	•	Allows empty values (not every customer uses every rate).

⸻

User Experience
	•	Customer page: has a Rate Sheet tab with two collapsible groups — Maintenance & Emergency and Snow & Ice.
	•	Empty fields display as “Not set” or gray placeholders.
	•	When rates are entered and saved:
	•	They display formatted as currency.
	•	“Last updated by [user], [timestamp]” appears below the sheet.
	•	Users can add an optional note (“Pricing exceptions or inclusions”).
	•	When viewing a Contract, relevant rates for that contract type show in a small “Applied Rates” panel for context.

⸻

Rules & Validation
	•	All rate entries must be valid numbers ≥ 0 (currency formatted).
	•	Empty fields are allowed and saved as “no rate set.”
	•	The system must distinguish between “0.00” (intentionally zero) and empty (not set).
	•	Saving updates “Last updated” info.
	•	Invalid entries (letters, negative values) are blocked with a clear message.

⸻

Permissions
	•	Admin / Office: can view and edit all rate fields.
	•	Ops / Viewer: view-only; edit controls hidden.

If an unauthorized user tries to save, show a clear “No permission to edit rate sheet” message.

⸻

Acceptance Criteria
	1.	Each customer shows a Rate Sheet tab with the correct categories and fields.
	2.	Admin/Office users can fill in rates, save, and reload to see correct values.
	3.	“Last updated by / on” displays after saving.
	4.	Invalid or negative inputs trigger a clear validation message.
	5.	Ops/Viewer users can open and view all rates but cannot edit.
	6.	On a Contract, the “Applied Rates” panel correctly shows related rate info (e.g., Maintenance contracts show Maintenance & Emergency labor; Snow contracts show Snow & Ice rates).

⸻

Test Checklist
	•	Fill out a few maintenance and snow rates, save, and verify they persist and display correctly.
	•	Leave some blank, verify blanks remain blank (not replaced with zeros).
	•	Enter text (“abc”) → blocked.
	•	Enter negative number → blocked.
	•	Switch roles (Admin → Ops) → see that editing is disabled.
	•	Open a Maintenance contract → see maintenance rates.
	•	Open a Snow contract → see snow rates.
	•	Edit again, save, check “last updated” timestamp refreshes.

⸻

Not included yet
	•	No per-service markups or formulas.
	•	No automated billing — this is a static rate reference used by your team.
	•	No rate history tracking (can be added later if needed).
