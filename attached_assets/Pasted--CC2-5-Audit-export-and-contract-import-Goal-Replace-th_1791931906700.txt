# CC2-5: Audit export and contract import

## Goal

Replace the Copy as the way existing contracts enter the Contract Center. The old records turned out to be too inconsistent to copy as they are (College Hills alone had wrong dates, the chemical and snow records misfiled, and an unrecorded renewal). Instead:

1. **Export:** an admin downloads a batch of customers. The zip has their old records and every attached contract document.
2. **Audit:** Claude reads each signed contract and fills in a set of import CSVs. Randy reviews them in Excel.
3. **Import:** an admin uploads the CSVs. **Preview** lists every problem; **Import** writes the contracts.

The Copy's Preview stays as a reference, but the **Copy button is disabled**. The legacy-link table (`term_legacy_sources`) and the documents already in storage are reused, so the revenue audit's "Open contract" links and the by-legacy redirect keep working.

Assumes CC2-1 to CC2-3 are merged (they are, as of `0b9e404`). **Line numbers are from GitHub `0b9e404`**; find code by its content. Every Phase 1 and Phase 2 rule applies.

## 1. Migration `0048_agreement_import_ref.sql` (0047 is `visits`; check that 0048 is still free)

```sql
ALTER TABLE agreements ADD COLUMN IF NOT EXISTS import_ref text;
DO $$ BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'agreements_company_import_ref_unique'
                 AND conrelid = 'agreements'::regclass) THEN
    ALTER TABLE agreements ADD CONSTRAINT agreements_company_import_ref_unique UNIQUE (company_id, import_ref);
  END IF;
END $$;
```

- Add `importRef: text("import_ref")` and the unique constraint to `agreements` in **both** schema files. Names must match the SQL so `check-schema-drift` passes.
- Agreements created any other way keep `import_ref` null. Postgres treats each null as distinct, so they don't collide.

## 2. Audit export

**`GET /api/admin/contract-center/audit-export?batch=<n>&size=<s>&documents=<true|false>`** (admin only)

- **Customers:** those that have at least one row in `contracts`, sorted by name (case-insensitive), then by id. `size` defaults to 10 (allowed 1–50). `batch` is 1-based.
- **`GET /api/admin/contract-center/audit-export/batches?size=<s>`** returns `[{ batch, firstName, lastName, customers, documents, bytes }]`, so the UI can show "Batch 3: Hunters Ridge – Lexington Estates (10 customers, 24 documents, 31 MB)".
- **Response:** a zip, streamed. Use `archiver` (add it to the api-server at an **exact** version) and pipe it straight to the response; never hold the whole zip in memory. File name: `contract-audit-batch-<n>-of-<total>-<YYYY-MM-DD>.zip`.

**Zip contents** (CSV: UTF-8, header row, RFC 4180 quoting; dates `YYYY-MM-DD`; money in dollars with 2 decimals):

| File | Contents |
|---|---|
| `manifest.json` | `{ exportedAt (ISO), batch, batches, size, customerIds, appVersion }` |
| `customers.csv` | customer_id, name, parent_customer_id, is_parent, management_company, address, city, state, zip, primary contact name/phone/email (whatever columns the customer record has) |
| `old_contracts.csv` | contract_id, customer_id, customer_name, service_type, billing_pattern, start_date, end_date, start_raw, end_raw, status, po, notes, mobilization_fee, updated_at |
| `old_monthly_amounts.csv` | contract_id, month (1–12), amount |
| `old_services.csv` | contract_id, service_type, annual_count, jan…dec (from `monthly_distribution`), service_parameters (JSON) |
| `old_rate_sheets.csv` | customer_id plus every rate column of `customer_rate_sheets`, in dollars |
| `old_documents.csv` | document_id, contract_id, customer_id, version, filename, mime_type, file_size, uploaded_at, zip_path |
| `contract_center.csv` | any existing Contract Center terms for these customers: agreement_id, import_ref, term_id, line, form, season, start, end, status, annual_price |
| `rate_card.csv` | the company's rate card: rate_key, line, category, label, price, price_text, unit, minimum, active |
| `documents/<Customer name>/<document_id>__<filename>` | every `contract_documents` file for the batch's contracts, all versions (skipped when `documents=false`) |

- `start_date`/`end_date` take the calendar date from the **UTC components**, the same rule the Copy uses. `start_raw`/`end_raw` are the stored ISO timestamps.
- Folder and file names: replace `/ \ : * ? " < > |` with `-` and trim them to 120 characters.
- **A document that can't be read from storage** is written to the zip as `documents/<Customer>/<document_id>__MISSING.txt` with the error. The export doesn't fail.

## 3. Import format

An import is a **zip of these CSVs** or the CSVs uploaded together. Column order doesn't matter; unknown columns are an error; blank cells mean "not given". Money is dollars (`1500`, `1500.00`, `1,500.00` and `$1,500.00` are all accepted). Parse it **as a string into integer cents**, never through floating point. Dates are `YYYY-MM-DD`. The template with a worked example is in `contract-import-template/` next to this file.

### `contracts.csv`: one row per season (term)

| Column | Required | Notes |
|---|---|---|
| `contract_ref` | yes | unique in the import, e.g. `college-hills-2026-27` |
| `agreement_ref` | yes | groups the seasons of one contract; becomes `agreements.import_ref` |
| `customer_id` | yes | must belong to the company and not be a parent customer |
| `customer_name` | no | check only: a mismatch with the customer's name is a **warning** |
| `line` | yes | `landscape`, `snow` or `both`; the same on every row of an agreement_ref |
| `form` | yes | `ours` or `theirs`; the same on every row of an agreement_ref |
| `season_label` | no | default: worked out from the dates, as `renewalDates` does (`2026–27`, or `2026`) |
| `start_date`, `end_date` | yes | checked with `validateDates` |
| `status` | yes | `draft`, `sent`, `signed`, `renewed`, `lost` or `cancelled` (`active` is accepted and stored as `signed`; the Contract Center works out "Active" itself) |
| `signed_date` | no | stored in `signed_at` as noon Colorado time on that date |
| `renews_ref` | no | the `contract_ref` this season renews; must be in the same agreement_ref with an earlier start date. Sets `renewed_from_term_id`. |
| `snow_pricing` | when line is snow or both | `time_and_materials` or `flat_rate` (checked with `validateSnow`) |
| `snow_flat_price` | when flat_rate | dollars |
| `managing_agent_name`, `legal_name`, `project_contact`, `contact_phone`, `contact_email`, `project_address`, `po`, `snow_triggers`, `notes` | no | copied to the term |
| `legacy_contract_ids` | no | old `contracts.id` values this season replaces, separated by `;`. Each must belong to the same customer. |
| `needs_review` | no | `true`/`false` (default false) |
| `review_note` | no | shown in the Needs review banner; items separated by `;` |

The agreement's `property_management_company_id` comes from the customer record, as in the New contract flow.

### `payments.csv`: one row per payment line per season

`contract_ref, payment_line, jan, feb, mar, apr, may, jun, jul, aug, sep, oct, nov, dec`

- Blank or 0 means no payment that month.
- These become the `payments` input of the CC2-1 functions: `validatePayments`, `paymentSummary` and `expandPayments`. Snow-only time-and-materials seasons must have no payment rows; that's an **error**.

### `rates.csv`: only where the contract differs from the rate card

`contract_ref, rate_key, price, price_text, minimum, unit, label, category, line`

- **A `rate_key` on the card** overrides that rate for the season. `price`, `price_text`, `minimum` and `unit` replace the card's values when given; blank keeps the card's.
- **A `rate_key` starting with `custom_`** is a custom rate. `label`, `unit`, `category` and `line` are then required.
- The season's rates are built with `snapshotRates(activeCard, overrides, line)`, exactly like Create, so every card rate is snapshotted.

### `scope.csv`: services included

`contract_ref, service_key, included, quantity, unit, jan, …, dec, label, notes`

- `service_key` is a `SCOPE_CATALOG` key, or `other:<slug>` with a `label`.
- The 12 month columns are the month spread. Leave all 12 blank for none. When given, they must add up to `quantity`, otherwise it's a **warning**.
- Built with `buildScope`. Seasons with no scope rows get none. Scope is only expected for current and upcoming seasons; past seasons can leave it out.

### `documents.csv`: attach documents already in the system

`contract_ref, document_id, kind`

- `document_id` is an old `contract_documents.id`. `kind` is `signed`, `their_form` or `other`.
- The import creates a `term_documents` row pointing at the **same** `storage_object_path`, keeping filename, mime type, size, uploader and upload date. No file is copied.
- A document whose old contract belongs to a different customer is an **error**.
- **Phase 7 note:** once term documents share storage objects with old documents, removing old rows must never delete the stored file. Add that to the Phase 7 notes in the design doc.

## 4. Import API and rules

- **`POST /api/admin/contract-center/import?dryRun=true|false`** (admin only, multipart). Accept one zip, or several `.csv` files. Limit: 10 MB. Parse with `csv-parse/sync` (exact version). `dryRun` defaults to true.
- **Validation runs in full on every call, before anything is written.** The response:
  ```ts
  {
    dryRun: boolean,
    errors: Array<{ file, row, column?, message }>,     // any error blocks the import
    warnings: Array<{ file, row?, contractRef?, message }>,
    customers: Array<{
      customerId, customerName,
      agreements: Array<{ agreementRef, line, form, action: "create" | "replace",
        terms: Array<{ contractRef, season, startDate, endDate, status, annualPrice, paymentLines, rates, scope, documents, needsReview }> }>,
    }>,
    summary: { customers, agreements, terms, replaced, documents, warnings, errors },
  }
  ```
  With any error the import does nothing, even when `dryRun=false`.

**Errors** (block the import):
- missing required values, bad dates, unknown status, line or form
- unknown customer, or a parent customer
- duplicate `contract_ref`
- `agreement_ref` rows that disagree on customer, line or form
- `renews_ref` that isn't in the same agreement, starts later, or forms a loop
- payment, rate, scope or document rows pointing at an unknown `contract_ref`
- anything the CC2-1 functions reject (`validateDates`, `validateSnow`, `validatePayments`, `paymentSummary`, `buildScope`, `snapshotRates`)
- unknown `document_id` or `legacy_contract_ids`, or ones belonging to another customer
- a legacy contract or document listed on two seasons
- a legacy contract already linked to a term **outside** the agreements this import replaces

**Warnings** (shown, don't block):
- `customer_name` doesn't match
- two seasons of one agreement overlap, and neither is `renewed`, `lost` or `cancelled`
- a scope spread doesn't add up to its quantity
- the customer already has Contract Center agreements with no `import_ref`; they're left alone
- **drift:** an old contract in `legacy_contract_ids` was updated after the export (`updated_at` > `manifest.exportedAt`, when the manifest is included): "Changed in the old system after the export; re-check"
- the customer has old contracts that no imported season lists in `legacy_contract_ids`: "Old contract <service type, dates> isn't covered by this import"
- an agreement being replaced has a term edited in the Contract Center after it was imported (`updated_at` later than its import history row): "Was edited after the last import; importing replaces those edits"

**Writing** (`dryRun=false`, no errors):
- One transaction **per customer**, like `executeLegacyCopy`. A failure rolls back that customer only and is reported.
- **Replace:** if an agreement with the same `import_ref` already exists for the company, delete it inside the same transaction. The cascade removes its terms, rows and legacy links. Then write it fresh. Re-importing a fixed CSV is therefore safe and creates no duplicates.
- **Create:** insert the agreement with `import_ref`. Insert the terms in start-date order so `renews_ref` resolves. Use the same row builders as Create: `buildScope`, `snapshotRates`, `expandPayments` and `paymentSummary` for `annual_price_cents` and `billing_type`, plus the legacy links and documents.
- **History:** each term gets one `term_status_history` row: old null → its status, `changed_by` the admin, note `Imported from audit (<upload filename>)`.
- Never touch the old tables.

## 5. Settings › Contracts screen

- **Audit export card:** batch size (default 10), a batch list from `/batches` with names, counts and size, a "Include documents" checkbox (on), and a **Download** button per batch.
- **Import card:**
  - a file drop that takes a zip or several CSVs
  - **Preview** shows the summary, then errors (red) and warnings (amber) grouped by file, then the customers table (agreement, seasons, dates, status, annual price, counts, `create`/`replace`)
  - **Import** is enabled only after a Preview with zero errors on the same files; it uses an inline confirm, never `window.confirm`
  - shows the result, including any per-customer failures
- **Copy card** (`components/contracts/LegacyCopyCard.tsx`): keep Preview. Disable Copy with the note "Contracts now come in through the audit import."
- **"Add missing standard rates"** stays as it is.

## 7. Tests

**Parsing:**
- `"$1,500.00"` → 150000, `"1645"` → 164500, `"0.10"` → 10
- `"1.005"` is an error (more than 2 decimals)

**Validation:**
- each error listed in section 4 is caught with its file and row
- a fully valid College Hills import (the template) gives zero errors and the expected warnings

**The template example (dry run):**
- **2025–26:** status renewed; one "Grounds maintenance" line; annual price $19,500 (Jul–Mar only).
- **2026–27:** renews 2025–26; status sent; needs review; payment lines "Grounds maintenance" $30,000 and "Chemical" $11,515; annual price $41,515.
- **Billing rows for 2026–27:** run Apr 2026 – Sep 2027, with 18 grounds rows and 13 chemical rows (Mar 2026 falls before the start).

**Writing:**
- importing twice leaves one agreement, with no duplicate terms or legacy links
- a failure in customer B leaves customer A imported
- documents point at the old storage paths, and no file is copied
- a legacy contract linked by an earlier Copy (outside the import) is an error

**Export:**
- batches are stable and sorted
- the zip has every file in section 2, with the dates taken from the UTC components
- a missing stored file gives `__MISSING.txt` and the export still completes
- non-admins get 403 on export and import
