⚠️ Recommended refinements (worth adding now)
1) Don’t mark “unsaved” on initial load

Your editor syncs objects from initialMarkup on mount, and your autosave effect triggers on objects changes. That can cause:

“Unsaved” immediately on load

a PATCH call even if user didn’t change anything

Add requirement:

Auto-save should only trigger after a user action modifies markup (not on initial hydration).

2) Clamp all points, not just drag targets

You clamp symbol/text points during drag. But polygon/polyline points can be added slightly outside bounds via click conversion near edges.

Add requirement:

All points are clamped to [0,1] when created/updated (polygon/polyline too).

3) Preserve aspect alignment explicitly (important)

Your layout relies on the <img> and <svg> sharing the exact same rendered box.

Add requirement:

The base <img> must be rendered without cropping (no cover).

Use a consistent “contain/fit” behavior so the SVG overlay matches the image bounds exactly.

(If later you add zoom/pan, this becomes more complex—but for VS2 this is the “don’t drift” rule.)

4) Text editing: prefer HTML overlay input, not <foreignObject>

foreignObject works in many browsers but can be inconsistent (especially with scaling, Safari quirks, and event handling).

Recommended requirement:

Implement text editing via an absolutely positioned HTML <input> overlay anchored to the selected text point (computed from SVG CTM / bounding box).

Commit on Enter/blur; Escape cancels.

This will save you days of weirdness.

5) Drawing UX: explicit “Finish” is optional but reduces confusion

Double-click finish is fine, but some users won’t discover it.

Add requirement (lightweight):

When drawing polygon/polyline and inProgressPoints.length >= 2, show a small inline hint near toolbar:

Polygon: “Click near first point to close, or double-click to finish.”

Polyline: “Double-click to finish.”

No new UI components needed — just visible guidance.

6) Object ordering should be deterministic

If you always append new objects at the end, selection in reverse order works well.

Add requirement:

New objects are appended to the end of objects[] (topmost).

Delete preserves order of remaining objects.

This prevents “why did it select the wrong thing?” complaints.

7) PATCH payload size guard (future-safe)

Even without exports, markupData can grow if users go wild with points.

Add requirement:

Enforce a reasonable max objects/points guardrail for VS2 (example: 200 objects OR 5,000 total points).

If exceeded, show a friendly warning (“Markup too complex—simplify shapes.”)

You may never hit it, but it prevents a single user from creating a slow/unreliable draft.

✅ Minor naming consistency

You’re mixing markup_data column name with markupData field—fine, but make sure UI and API consistently refer to it as Markup (user-facing).

One small conceptual note

Your symbols list uses a “Boulder icon = Circle” from lucide. Totally fine for MVP. If you later want it more “landscape-native,” you can swap icons without changing data.
