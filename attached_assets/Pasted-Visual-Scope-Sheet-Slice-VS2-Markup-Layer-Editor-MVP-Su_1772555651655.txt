Visual Scope Sheet — Slice VS2 (Markup Layer Editor MVP) — Submit This Whole Block
Goal

Add a reliable markup/drawing layer on top of the stored base image so users can create simple visual scopes (shapes, symbols, and labels) that persist as editable structured data. This slice focuses on creating and saving markup — no exports and no proposal integration yet.

Guardrails (What NOT to build yet)

Do not generate exported images (no base/overlay/combined files yet)

Do not integrate into Proposal Maker yet

Do not add GIS features (no georeferencing, measurements, sqft calcs)

Do not add advanced design tools (no freehand brush, layers panel, complex styling)

Do not implement versioning/finalization yet (that will be a later slice)

Requirements
1) Markup Data Model (Structured, Editable)

Markup must be stored as structured objects tied to a Visual Scope Sheet draft (VS draft).
Do not bake drawings into the base image.

Each markup object must store, at minimum:

Unique object id

Object type: polygon | polyline | symbol | text

Geometry (coordinates relative to the base image/canvas)

Style (limited, brand-safe)

Created by + created date (optional but preferred)

Coordinate system requirement

Store coordinates in a way that survives different screen sizes and zoom levels (normalized to the base image/canvas, not raw screen pixels).

2) Editor UI (On the VS Draft Page)

On the VisualScopeDraft page, when a base image exists:

Display the base image with a markup overlay layer above it

Provide a simple toolbar of tools (see below)

Provide object selection + editing behaviors

All changes must persist and reload after refresh

3) Tools Included (MVP Set)
Geometry Tools

Polygon

Click to place points

Close polygon to finish

Must be selectable after creation

Polyline

Click to place points

Double-click or “Finish” action to complete

Must be selectable after creation

Symbol “Stamp” Tools (Preset Icons)

Provide at least these 3 preset symbol types:

Plant

Tree

Boulder

Stamp behavior:

Click to place symbol on the image

Symbol must be movable after placement

Symbol uses a consistent size (simple scale options optional)

Text Label Tool

Click to place a text label

Prompt for text (or inline edit)

Labels must be movable after placement

4) Editing Behaviors (Must-Have)

For all markup objects:

Select an object by clicking it

Move symbols and text labels via drag

Delete selected object

Edit:

Text labels editable after creation

Polygons/polylines: at minimum allow delete + redraw; optional vertex editing is allowed but not required in VS2

Undo/Redo

Optional in VS2 (nice to have), not required

5) Styling Rules (Keep It Professional)

Limit colors to a small, brand-safe palette:

Primary brand green (for headings/primary shapes)

Neutral gray

Accent color (optional)

Limit line thickness to 2–3 options (or just one default)

Avoid decorative effects (no shadows, glows, gradients)

6) Legend (On-Screen Only, No Export Yet)

Add a simple “Legend” panel on the VS Draft page that auto-populates based on symbols used:

Tree: {count}

Plant: {count}

Boulder: {count}

Rules:

Legend updates automatically as symbols are added/removed

Legend is for editor display only in VS2 (export comes later)

7) Persistence + Auto-Save

Markup changes must persist reliably

Saving strategy can be:

explicit “Save” button, or

auto-save with debounce

Must not lose changes on refresh after save completes

8) Permissions

Same as VS1:

Admin + Office: full access

Other roles: no access (unless specified later)

Acceptance Tests

Create a VS draft with a base image (VS1 flow)

Add a polygon and refresh → polygon persists

Add a polyline and refresh → polyline persists

Place 3 symbols (Tree/Plant/Boulder) and refresh → all persist

Legend counts match placed symbols and update on delete

Add a text label, edit it, refresh → edited text persists

Delete an object, refresh → object remains deleted

Symbols and labels can be dragged to reposition and persist correctly

Markup remains aligned to the base image when resizing the browser window

Done Definition

Users can open a Visual Scope Sheet draft with a base image, add and edit simple markup (polygons, polylines, stamp symbols, text labels), see an auto-generated legend (on screen), and reliably reload the draft with all markup intact. No exports or proposal integration are included yet.
