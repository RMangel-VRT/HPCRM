# Slice V2 — Ticket detail: solid type identity, no tinted surfaces

**Scope: exactly one file — `artifacts/highplains-crm/src/pages/TicketDetail.tsx`.**
No CSS token changes. No server changes. No other component.

## Why

Slice V1 carried ticket-type colour as a translucent wash: a `linear-gradient` at
`var(--tt-tint2)` (13% light / 17% dark) over the header, plus `color-mix` fills at
`var(--tt-tint)` on the type badge and the current work-thread node. On a white page a
13% wash reads as a smudge, not as identity — and it cannot be fixed by turning it up,
because at 30% it stops being a background and starts fighting the text.

**The rule this slice installs: ticket-type colour only ever appears at full strength,
on a small opaque object.** Nothing gets a tint. Specifically the hue appears on:

* a 4px solid line across the **top** of the header card
* the **icon tile** inside the type badge (solid fill, inverted glyph)
* the **icon tile** on each work-thread node
* a 3px solid **left edge** on the current work-thread node
* the **active tab underline**

Everything else — header background, card backgrounds, badge backgrounds — becomes plain
`var(--background)` / `var(--card)`. The status pill is the one soft fill that stays, on
purpose: status appears on every row and should not shout, while type is the thing the
user is meant to catch at a glance.

This slice also replaces the sparse `grid-cols-2` summary with a dense metadata strip
inside the header card.

## Facts established by analysis — do not deviate from these

These were checked against the current commit. Several contradict what a
"make it look like the mockup" reading would assume.

* **There is no scheduled-date column on tickets.** `grep` for `scheduledDate` /
  `scheduledStart` / `scheduled_date` in `TicketDetail.tsx` returns nothing. Do **not**
  add a "Scheduled" cell to the metadata strip. There is nothing to put in it.
* **`crewsList` is gated.** `const { data: crewsList = [] } = useQuery({ queryKey:
  ["/api/crews"], enabled: showEditDialog })` at ~L263. It is empty until the edit dialog
  opens. Do **not** add a "Crew" cell reading from it — it would render blank on load.
  Do **not** change `enabled` either; that adds a query to every ticket page load.
* **The capability flags DO reach the client.** `GET /api/tickets/:id/details` calls
  `storage.getTicketTypeById`, which is `db.select().from(ticketTypes)` — a full-row
  select — so `ticketType.requiresInvoicing` and `ticketType.requiresScheduling` are
  present at runtime as the strings `"true"` / `"false"`.
* **They are untyped.** `TicketType` comes from `@shared/schema`, whose `pgTable()` is
  declared `: any` on the drizzle stub. So `ticketType.requiresInvoicing` compiles no
  matter what. Always compare explicitly: `ticketType?.requiresInvoicing === "true"`.
  Never rely on truthiness — the string `"false"` is truthy.
* **`card-ticket-summary` contains interactive controls**: the reassign `<Select
  data-testid="select-reassign-ticket">` and the `data-testid="delegation-indicator"`
  block. Both must survive this slice. See Step 6.
* Available in scope after the L708 destructure: `ticket`, `ticketType`, `customer`,
  `assignedUser`, `priority` (L709), `currentStatus` (L710), `linkedTickets`.
* `WORK_TYPE_CATALOG` is already imported at L79.

## Step 1 — Header wrapper: kill the gradient, add the top edge

Find the wrapper immediately inside `return (` — currently:

```tsx
<div
  className="rounded-xl border px-3 py-3 -mx-1"
  style={{
    background: `linear-gradient(180deg, color-mix(in srgb, ${hue} var(--tt-tint2), transparent) 0%, transparent 100%)`,
    borderColor: `color-mix(in srgb, ${hue} 22%, var(--border))`,
  }}
>
```

Replace with:

```tsx
<div
  className="rounded-xl border border-t-4 overflow-hidden -mx-1"
  style={{
    borderColor: `color-mix(in srgb, ${hue} 20%, var(--border))`,
    borderTopColor: hue,
  }}
  data-testid="header-ticket-identity"
>
  <div className="px-3 py-3">
```

and **close that new inner `<div>`** immediately after the existing
`data-testid="button-delete-ticket"` block's closing `</div>` — i.e. the inner wrapper
contains exactly the existing `<div className="flex items-center gap-2">…</div>` row and
nothing else. The metadata strip in Step 3 goes *after* the inner div, still inside the
outer one.

**Key ordering matters.** In the style object `borderColor` must come *before*
`borderTopColor`. React applies style properties in object-key order; `borderColor` is a
shorthand that resets all four sides, so if it came second it would silently erase the
top colour and the whole feature would vanish with no error.

`overflow-hidden` is required so the full-bleed strip in Step 3 is clipped by the card's
rounded corners.

Notes:
* `background` is removed entirely — no replacement. The card inherits the page.
* `px-3 py-3` moves to the inner div; `-mx-1` stays on the outer.
* `var(--tt-tint2)` now has no reader in this file. Leave the token in `index.css` —
  removing it is out of scope and other slices may adopt it.

## Step 2 — Type badge: solid tile, not a tinted pill

Replace the whole `data-testid="badge-ticket-type"` span (L1027–1040) with:

```tsx
<span
  className="inline-flex items-center overflow-hidden rounded-md border bg-background"
  style={{ borderColor: `color-mix(in srgb, ${hue} 38%, var(--border))` }}
  data-testid="badge-ticket-type"
>
  <span
    className="flex w-6 self-stretch items-center justify-center"
    style={{ background: hue, color: "var(--tt-on-hue)" }}
  >
    <TypeIcon className="h-3.5 w-3.5" />
  </span>
  <span
    className="px-2.5 py-1 text-[12px] font-semibold whitespace-nowrap"
    style={{ color: `color-mix(in srgb, ${hue} 82%, var(--foreground))` }}
  >
    {ticketType.name}
  </span>
</span>
```

`--tt-on-hue` does not exist yet. **Add it to `artifacts/highplains-crm/src/index.css`**,
beside the existing `--tt-tint` declarations:

* in the `:root` block (near L144, where `--tt-tint: 15%;` lives): `--tt-on-hue: #ffffff;`
* in the `.dark` block (near L278, where `--tt-tint: 24%;` lives): `--tt-on-hue: #17170f;`

The flip is required, not cosmetic: the dark-theme type hues (`#7a6ff0`, `#3ca694`,
`#be47b8`, `#cf7132`, `#9a9a90`) are light colours, and a white glyph on them fails
contrast. A near-black glyph passes on both.

*(This is the only `index.css` edit in the slice.)*

## Step 3 — Dense metadata strip

Directly after the inner `px-3 py-3` div closes, still inside the header card, add:

```tsx
<div
  className="flex flex-wrap border-t bg-muted/40"
  data-testid="strip-ticket-meta"
>
  {[
    customer ? { label: t('common.customer'), value: customer.name } : null,
    { label: t('ticketDetail.assignedTo'), value: assignedUser?.email ?? t('common.unassigned') },
    { label: t('common.priority'), value: priority.label },
    ticket.workType && WORK_TYPE_CATALOG[ticket.workType as WorkType]
      ? { label: t('tickets.workType'), value: WORK_TYPE_CATALOG[ticket.workType as WorkType].billingLabel }
      : null,
    { label: t('ticketDetail.dueDate'), value: ticket.dueDate ? format(new Date(ticket.dueDate), "MMM d, yyyy") : t('common.none') },
    ticket.workCompletedDate
      ? { label: t('ticketDetail.workCompletedDate'), value: format(new Date(ticket.workCompletedDate), "MMM d, yyyy") }
      : null,
  ]
    .filter((cell): cell is { label: string; value: string } => cell !== null)
    .map((cell, index) => (
      <div
        key={cell.label}
        className={`min-w-0 flex-auto px-4 py-2 ${index === 0 ? "" : "border-l"}`}
      >
        <p className="text-[10px] font-bold uppercase tracking-[0.07em] text-muted-foreground">
          {cell.label}
        </p>
        <p className="truncate text-[12.5px] font-medium">{cell.value}</p>
      </div>
    ))}
</div>
```

The `border-l` is on every cell except the first rather than `border-r` on every cell
except the last, so a wrapped second row still starts flush.

`format` and `WorkType` are already imported and used in this file — confirm before
adding any import.
