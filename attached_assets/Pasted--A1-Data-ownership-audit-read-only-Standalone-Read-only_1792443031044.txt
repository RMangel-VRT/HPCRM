# A1: Data ownership audit (read-only)

> **Standalone. Read-only. No code changes, no schema changes, no data writes, no publish.** The only file you create is the report `docs/data-ownership-audit.md`. You may also add a throwaway script under `scripts/audit/`, but it must not be imported by the app. Read `.agents/memory/` first. Base: current `main`; find code by its content.

## Why

Randy wants **one source of truth for every fact** in the system. The rule:

> Every fact has exactly one owner. Any other copy must be either a **deliberate snapshot** (e.g. the prices on a signed contract, the crew that actually did a completed visit) or an **automatic mirror** maintained by one function (e.g. a ticket's `crew_id` / `due_date` mirrored from its visits). If two places can disagree and nothing reconciles them, that's a duplicate.

This audit turns a suspected list into facts: what each table holds, whether it's still used, and who reads and writes it. Later slices retire duplicates one area at a time (pick owner → copy in → switch readers and writers → freeze → drop after a season). **This slice decides nothing and changes nothing.**

## Rules

1. **Production access is read-only SELECTs**, through the same authorized access used for the C3, P3-1 and P3-2 reports.
   - Report **counts, dates and names of things** (crews, templates, service keys, categories) only.
   - **No customer names, addresses, contact details, email bodies or credentials.**
   - If production access isn't available, say so at the top and stop the production part; don't substitute dev data.
2. **Label every number with its environment and timestamp.**
3. **Code references** come from grep plus reading: every route, storage function, page and component that **reads** or **writes** each table. Count `db.insert/update/delete`, storage create/update/delete helpers and raw SQL as writes. Count select/join as reads. Include the mobile app (`artifacts/highplains-mobile`) and boot fix-ups in `registerRoutes`.
4. **Don't fix anything you find.** List it.

## 1. Per-table inventory (every table, not just the suspects)

For **all tables** in `lib/db/src/schema/schema.ts` (about 113), one row each:

| Column | Meaning |
|---|---|
| Table | name |
| Area | your grouping (crews, contracts and scope, services, rates, contacts, templates, messages, notes and photos, equipment, scheduling, seasons, tickets, maps, plants, auth, other) |
| Prod rows | `count(*)` |
| Rows created in the last 90 days | if it has `created_at` |
| Newest write | `max(greatest(created_at, updated_at))`, whichever exist |
| Readers | count of code sites plus the main screens and endpoints |
| Writers | the same |
| FKs in / out | the tables that reference it, and the tables it references |
| Status | **Active** (written in the last 90 days, or written by a live screen), **Read-only** (still read, never written now), **Frozen** (writes deliberately blocked, e.g. legacy contracts), or **Dead** (no live readers or writers) |

Put this full table in an appendix. The body of the report covers the areas below.

## 4. Report format: `docs/data-ownership-audit.md`

1. **First line:** "N areas have live duplicates; M tables look dead; K copied columns have drifted."
2. **A one-screen summary table:** area · holders · prod rows · disagree? · suggested owner · effort (S/M/L) · risk notes.
3. **One section per area (A–M, plus any new ones)**, in the format above.
4. **Dead and read-only tables:** everything with no live writers, and whether anything still reads it.
5. **Things that would make retiring hard:**
   - cascade deletes (e.g. `schedule_blocks` cascading from `maintenance_crews`);
   - mobile app dependencies;
   - QuickBooks links;
   - generated API clients;
   - Replit Publish behavior around dropped tables (see `.agents/memory/` and the Sept 2 phantom-drop incident).
6. **Appendix:** the full per-table inventory from §1, and the vocabulary mapping table from area C.

## Done when

- Every table is in the appendix, with prod rows, last write, readers and writers, labeled with environment and time.
- Areas A–M are answered with production counts and code references, plus any new areas found.
- The vocabulary mapping table is complete.
- No code, schema or data was changed. `git diff` shows only the report (and the optional unused script).
